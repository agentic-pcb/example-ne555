## Status

NE555 5 V LED flasher, 2-layer, 23.6 x 16.2 mm. Builds cleanly (`tsci build`), `tsci check shorts` and `tsci check placement` (0 errors) and `npm run check:vias` (9 vias, all 0.6/0.3 mm) are clean; audited against all 66 rules of `LAYOUT_RULES.md` and the `CIRCUIT_RULES.md` of 2026-10-10, including every `Don't:` clause (exceptions are listed in the audits). Not yet fabricated or tested on hardware.

## Project map

What Claude needs to know before touching this project. `CLAUDE.md` is the shared template, identical to the one in `agentic-pcb/example-base` and never edited here (`npm run update:claude` refreshes it); everything specific to this project is in this README.

- **Boards:** `index.circuit.tsx` (the `mainEntrypoint`), a 5 V NE555 LED flasher.
- **Scripts:** the plain names (`check:fast`, `check:wiring`, `check:vias`, `check:full`, `export:images`, `export:gerbers`, `dev`, `update:claude`, `update:skill`, `update:llms`); `check:vias` runs `scripts/check-vias.mjs` (copied from example-base) on `dist/index/circuit.json` and is part of `check:full`; no other project-specific script.
- **README images:** `__snapshots__/index.circuit-schematic.snap.svg`, `docs/images/pcb.png`, `docs/images/3d.png`.
- **Tooling:** no formatter or linter.
- **Layers and vias:** `<board layers={2}>` (rule 64) with `routeRemaining={false}`: every trace carries an explicit `pcbPath` (a trace without one gets no copper; `pcbPath={[]}` is a straight pad-to-pad segment, and hand-routed traces default to 0.1 mm, so each sets `thickness`). Without a size on the board the installed core makes every via 0.3 mm pad / 0.2 mm hole, which JLCPCB charges for, so the board sets `pcbStyle={{ viaPadDiameter: 0.6, viaHoleDiameter: 0.3 }}` (rule 66; it sizes hand-routed and autorouted vias and the pour's) and `npm run check:vias` fails on any via or plated hole below 0.3 mm hole / 0.45 mm pad.
- **Rules:** `LAYOUT_RULES.md` (rules 1-66) and `CIRCUIT_RULES.md` apply to the whole board. The audits are "Design rule audit" (one row per layout rule) and "Circuit rules audit" (one row per applicable rule) below; when the rule numbers change upstream, renumber the tables and the rule references in this README and in `index.circuit.tsx`. Known documented exceptions: the timing cap is not C0G (no 10 uF C0G in 0603), there is no input protection (bench-supply board), R1/R3 carry a 0.3 mm V5 trace on one pad and a 0.15 mm signal on the other (rule 62, one width per trace), and the DC-bias curve of C1 was not read (CIRCUIT_RULES C3 Don't).
- **Helpers and gotchas of this board:**
  - Footprints: U1 and D1 deliberately use local `<footprint>` definitions (pad geometry copied from the JLCPCB parts) and pass `cadModel` with absolute `modelcdn.tscircuit.com` URLs; keep that pattern for other JLCPCB-specific parts. The `NE555` wrapper forwards `schSheetName` to the chip.
  - Silkscreen: J1 (pin labels, designator, the rule 43 `Power` group label and its `<silkscreenline>`) hides its own texts and uses explicit elements. U1 and D1 have no text in their local footprints, so their designators are explicit `<silkscreentext>` too, and U1's pin-1 dot is a `<silkscreencircle>` in its footprint. Rule 37 (0.5 mm courtyard gap, 1 mm to a header) and rule 43 set the board width (see Requirements): J1's rotated courtyard is 3.54 x 6.08 mm.
  - Schematic: the sheet is 220 x 95 mm and `schMaxTraceDistance` is 5. Sections: `Power`, `Core`, `Timing`, `Output`. On U1 the inputs are on the left, OUT/DISCH on the right, VCC on `topSide` and GND on `bottomSide` of `schPinArrangement`, with OUT listed above VCC (this fixed the D1/OUT wire overlapping the VCC wire). The J1 power block is joined by V5/GND labels only, so it stays more than 5 units from every V5/GND pin of the neighbouring blocks (J1 at `schX=-12.5` is fine).
  - R2 is intentionally not flipped: the `TwoPinComponentCouldBeFlipped` hint would loop the TRIG wire back across DISCH.
  - C3 is wired pin2 = V5 / pin1 = GND (a capacitor is non-polar) so its V5 pad is the one nearer U1 VCC on the PCB; it is rotated 270° in the schematic and placed straight above U1 VCC so V5 faces down onto the pin. The `InvertedRails` hint of `check schematic-placement` is then expected, and its GND pin must stay more than `schMaxTraceDistance` from the other GND pins, otherwise it is wired across the sheet.
  - Copper: the `route(at, pts, d)` helper builds `<trace pcbPath>` and cuts every 90 degree corner (rule 17); it drops the first and last point (the pads). `from` must be a 0° part and `at` its `pcbX`/`pcbY` (`R1`, `C1`, `U1` constants hold the anchors used by traces that start on another part; `OUT` starts at the rotated D1, so its points are converted into D1's frame). `gndVia(at, via)` makes the pad -> via stub of a GND pad and `hop(at, a, b)` the crossing hop of rule 65 (wire point, via, short bottom segment, via, wire point: a via inside a path needs a wire point at the same spot on both sides). V5 is hand-routed as a whole net and its pin-to-pin traces carry `schDisplayLabel="V5"`. The `from`/`to` of every trace is the one that draws the schematic wire, so a net that needs copper between other pads overlaps another trace of the same net (`T13` passes through C1.pin1 over `T12`); only the DISCH flag side changed against the pre-rules schematic. C3 sets `maxDecouplingTraceLength={3}` (C4: 6) and no long trace starts at C3. `T2` (J1.GND) and `T10` (R1.pin1 to `net.V5`) are single-point traces that only declare the net.

## Requirements

- **Purpose:** flash a red SMD LED, about 0.33 s ON / 0.65 s OFF (1:2 ratio, period ~1 s), using an NE555.
- **Board size / form factor:** 23.6 x 16.2 mm (382 mm²), 2 copper layers, all parts on the top side. The width is set by D1 (rule 26: an assembled body at least 2.5 mm from the edge, D1 pad edge 2.51 mm), by J1's left-hand label stack (pin labels, rule 43 `Power` group label, 1.27 mm to the edge by rule 26) and by the top-right hole's 3 mm free circle clearing R3 (rule 18); the height by C4's pad edge (2.55 mm below the top edge, rule 26) and its designator above J1 (rule 8). The 0603 core (two rows at y = +-3.81, pitch 3.81) is already at the smallest 1.27 mm-grid spacing that keeps the 0.5 mm courtyard gap of rule 37, so it cannot be tightened. The pre-rules outline was 23.2 x 15.3 mm; the 2.5 mm body-to-edge rule for assembled parts (rule 26) put C4 (2.10 mm) and D1 (2.31 mm) out of it, so the board grew by 0.4 x 0.9 mm (the parts keep their coordinates; the origin is still the board centre).
- **Power sources and rails:** single 5 V input on a 2-pin 2.54 mm header (J1: `V5`, `GND`). NE555 minimum supply is 4.5 V, so 5 V is fine.
- **I/O (connectors, headers, mounting holes):** J1 power header, 2x 3.2 mm (M3) mounting holes on one diagonal (top right and bottom left, 9.42 mm from the centre in x, 5.72 mm in y, 2.38 mm from both edges of their corner). The area within 3 mm of each hole centre is kept free of parts, pads and silkscreen (LAYOUT_RULES.md rule 18). The other diagonal does not work: its top-left hole would sit 2.3 mm from the J1 designator.
- **Mechanical constraints:** none beyond the above.
- **Manufacturer and constraints:** JLCPCB; all resistors/capacitors 0603; basic parts where one exists; Economic assembly (only parts marked "PCBA Type: Economic and Standard", never "Standard Only").

## Design notes

- **Timing:** a normal 555 astable has HIGH longer than LOW, so the LED is wired from V5 through R3 to the LED and sunk into OUT (pin 3). It is ON while OUT is LOW: ON = 0.693*R2*C1, OFF = 0.693*(R1+R2)*C1. Equal ON/OFF ratio 1:2 means R1 = R2. With R1 = R2 = 47 k and C1 = 10 uF: ON = 0.326 s, OFF = 0.651 s (period ~0.98 s). 47 k is a JLCPCB basic part (CIRCUIT_RULES R8; 43 k, which would give 0.298 / 0.596 s, is an extended part); about 0.33 / 0.65 s is close enough for a visual flasher.
- **Capacitor choice (CIRCUIT_RULES C3, Capacitors table):** C1 is a 10 uF **25 V** X5R 0603 ceramic (C96446, CL10A106MA8NRNC, basic, +-20 %). A 10 V part would lose a large fraction of its capacitance to DC bias on a 5 V rail; C3 asks for a 16/25/50 V rating on a 5 V rail, so the 25 V part keeps the period much closer to nominal (the exact loss is in the Samsung DC-bias curve, not measured here). The table asks for C0G on timing caps, but C0G, film and low-ESR polymer/tantalum parts do not exist at 10 uF in 0603 (or are polarised, larger and "Standard Only", which breaks Economic assembly), so X5R stays as a documented exception. The 1:2 ON/OFF ratio is unaffected by C1 (it only depends on R1/R2), and a visual LED flasher needs no accurate period; if it ever matters, measure the assembled board and trim R1/R2 (keep R1 = R2). A 1 uF 50 V C1 would need R1 = R2 = 470 k, where the bipolar NE555's TRIGGER/THRESHOLD bias currents add their own error.
- **Bulk capacitor (CIRCUIT_RULES C1, LAYOUT_RULES.md 41):** C4 (10 uF 25 V X5R, C96446, same part as C1) sits directly above J1 (5.08 mm centre to centre, tier 1 of the three-tier decoupling; C3 100 nF is tier 2 at U1 VCC). It is joined to the V5 node at R1.pin1 by the hand-routed trace `V5_C4`, its GND pad runs to J1.GND, and `maxDecouplingTraceLength={6}` is set because the default 1 mm limit would stop the autorouter (J1.GND is about 4 mm away). On the schematic its pins are V5/GND label stubs, kept more than `schMaxTraceDistance` from J1: closer, tscircuit draws long wires round J1 that cross each other.
- **Input protection (CIRCUIT_RULES PR-1..3, PR-2, FUSE-1; documented exception):** J1 has no fuse, reverse-polarity protection, ESD or overvoltage part. This is a bench-supply example board; a series diode would also cost about 0.3 V of the 0.5 V margin between 5 V and the NE555's 4.5 V minimum supply (a 4.75 V USB rail would not work), and a P-MOSFET (Q5) adds parts and area. Add one if the board is ever fed from an uncontrolled source.
- **LED current:** (5 V - ~2.3 V - ~0.2 V OUT low) / 330 ohm ~= 7.6 mA (XL-1608SURC-06, Vf 2.3 V typ).
- **555 housekeeping:** RESET tied to V5, CTRL decoupled by C2 (10 nF), C3 (100 nF) decouples the supply at U1.
- **Footprints:** U1 (SOIC-8) and D1 (0603 LED) use local `<footprint>` definitions with the pad geometry copied from the JLCPCB parts. `footprint="jlcpcb:..."` fetches from the EasyEDA API at build time and fails when it rate-limits (HTTP 403), so avoid it. D1 pin 1 is the cathode (K) on C965799 and is mapped that way. Their 3D bodies are the generic tscircuit models `jscad_models/soic8.glb` and `led0603.glb` from modelcdn.tscircuit.com (via `cadModel`), because custom footprints get no 3D body otherwise.
- **Part numbers:** `supplierPartNumbers={{ jlcpcb: [...] }}` is set on every assembled part with the chosen LCSC numbers (`index.circuit.tsx` is the single source of truth for the BOM). The BOM export only lists parts that carry a supplier part number: without it U1 (custom-footprint chip) and D1 would be missing from the fab export, and the parts engine would auto-pick other LCSC parts for the passives. The parts engine is disabled (`tscircuit.config.ts` `partsEngineDisabled`, plus `--disable-parts-engine` in the npm scripts): otherwise tscircuit fetches every pinned part from EasyEDA only to cross-check its footprint, which floods the build with warnings when EasyEDA rate-limits (HTTP 403). **Economic assembly:** every part must show "PCBA Type: Economic and Standard" on its jlcpcb.com part page (never "Standard Only"); all current parts do. D1 (C965799, the basic red LED is only 0805; C84263 is Standard Only), and U1 are extended parts, the rest are basic (R1/R2 47 k C25819, CIRCUIT_RULES R8; C1 and the bulk cap C4 are both C96446).
- **Assembly:** J1 is `doNotPlace` (through-hole header, hand-soldered) so it stays out of the JLCPCB BOM/CPL; everything else is SMD on the top side.
- **Ground pour:** solid copper pour on the bottom layer only, tied to GND (0.2 mm clearance, `boardEdgeMargin="1.27mm"`; LAYOUT_RULES.md rule 16 says no top pour). Every top-layer GND pad (C1, C2, C3, C4, U1.GND) has its own GND via beside the pad, joined by a short stub (rules 16, 24, 65); J1.GND is a through-hole pad and sits in the pour directly. The two bottom-layer hops (1.85 and 1.59 mm) are the only other bottom copper, so the pour stays one piece.
- **Trace width:** V5 and GND traces are 0.3 mm (`thickness="0.3mm"`), signal traces 0.15 mm (set explicitly: a hand-routed trace defaults to 0.1 mm). The GND stubs at C1 and C2 are 0.15 mm so both pads of those caps are fed alike (rule 62, a 0.9 mm stub; the pour carries the current). R1.pin1 and R3.pin1 keep their 0.3 mm V5 traces against a 0.15 mm signal on the other pad: a tscircuit trace has one width, so the neck of rule 62 cannot be drawn there (see Decisions).
- **Routing:** the whole board is routed by hand (`routeRemaining={false}`), 9 vias in total, all 0.6 mm pad / 0.3 mm hole and none on V5 (rule 15). V5 runs on the top layer through the `route()` helper (rule 17, no vias). GND: five pad -> via stubs, J1.GND in the pour. Signals: CTRL, LED_A, T12 are straight pad-to-pad; OUT leaves U1 between THRES and CTRL (y = -1.27) and runs straight to D1; DISCH goes from R1.pin2 under the IC body to U1.DISCH. Two crossings are forced by the NE555 pin order and the part rows, and each is one two-via hop (rule 65, no 0 ohm jumper, no detour): R1.pin2 to R2.pin1 crosses the V5 wall J1.V5 -> T4 -> RESET (hop at x = -3.9, 1.85 mm bottom segment), and the THRES net (C1.pin1 / R2.pin2 to U1.THRES and TRIG) crosses OUT (hop at x = 0.445, 1.59 mm). T1 runs at x = -5.18, between J1 and the rest of the board, so the labels on J1's left stay clear of copper. Hand-routed traces anchor their `pcbPath` to the `from` part's centre, and C3 has `maxDecouplingTraceLength={3}` (the 1 mm default would stop the autorouter, since its V5 pad is 2.60 mm from U1 VCC). Smallest clearance between different nets 0.255 mm (OUT past the THRES via and the THRES/CTRL pads), measured from `dist/index/circuit.json`. Sensible to review in `tsci dev` before fabrication.
- **Layout:** see the published [LAYOUT_RULES.md](https://github.com/agentic-pcb/example-base/blob/main/LAYOUT_RULES.md); the "Design rule audit" table below audits rules 1-66. The board corners are rounded with a 2 mm radius (rule 28). Parts sit on a 1.27 mm grid in two rows of three 0603 parts (top y = +3.81: R1, C3, R3; bottom y = -3.81: R2, C1, C2; 3.81 mm pitch at x = -2.54 / 1.27 / 5.08), with U1 at (1.27, 0), J1 at x = -6.35 and D1 at x = 8.89 on the centre line. The whole layout is shifted 1.27 mm to the right of the board centre so the left margin (J1's `Power` label, 2.30 mm) and the right margin (D1's courtyard, 2.01 mm; its pad 2.51 mm) are nearly equal. The bulk cap C4 sits alone above J1 at (-6.35, 5.08), 1.31 mm from J1's courtyard; the holes are on the free diagonal (top right, bottom left). Every pad is at least 3.43 mm from a hole centre (screw head area, rule 18). Courtyard gaps (rule 37): J1 to R1/R2 0.56 mm, J1 to C4 1.31 mm, J1 to U1 2.15 mm, U1 to the 0603 parts 0.68 mm, C4 to R1 0.85 mm.
- **Decoupling (rule 24, a must):** C3 (100 nF) sits directly above U1 pin 8 (VCC), 2.60 mm centre to centre. Its V5 pad is pin 2 (a capacitor is non-polar, so pin 1/pin 2 are swapped in the TSX) so the V5 pad is the one nearer VCC. Its GND pad has its own via 0.6 mm to the left (hole edge 0.45 mm from the pad), not shared and not in the pad (rules 24, 61). C2 (CTRL bypass) sits below pin 5.
- **Silkscreen:** designators 0.4 mm, 1.1 mm above their part (`pcbSx`; the GND vias sit beside the pads, clear of the designators and of the cap outlines); U1 and D1 have no text in their local footprints, so their designators are explicit `<silkscreentext>` elements above the part. J1's V5/GND labels (0.5 mm, x = -7.70) and the `Power` group label (rule 43: 0.6 mm, x = -9.20, 1.5 mm further out) with its `<silkscreenline>` along the pins (x = -8.43) are explicit elements too, because `pcbSx` cannot tell a designator from a pin label. U1 pin 1 is marked with a `<silkscreencircle>` in its footprint (rule 42); D1 has its cathode bar.
- **Schematic:** four `<schematicsection>`s (Power input: J1 + C4, Timer core, Timing network, LED output) read left to right on a 220 x 95 mm sheet; U1 sits in the middle with CTRL/TRIG/THRES on the left, OUT/DISCH on the right, RESET + VCC on top and GND at the bottom (only the symbol changes, the netlist does not), J1 at the lower left. C3 sits straight above VCC (its V5 pin faces down to the pin, so `tsci check schematic-placement` prints an informational `InvertedRails` hint for it; the straight wire is kept on purpose) and its GND pin is more than 5 units from the other GND pins so it gets a label stub instead of a long wire. C2 sits left of U1 with one bend to CTRL and one to GND. C4 (bulk cap, Power block) sits above J1 with V5/GND label stubs only (see the C4 note above; rule 30 exception). The `DISCH` flag sits on the right of the R1-R2 wire (its trace now starts at R1.pin2, so the copper does not repeat the R2.pin1 hop). Trace names that tscircuit draws are meaningful: `DISCH`, `THRES` (flags), `CTRL`, `LED_A`, `OUT` (small net names beside two-pin wires/stubs).

## Decisions

- **Stitching vias:** none. The published rule 16 pours the bottom layer only and joins top-layer GND pads to it with GND vias; there is no top pour to stitch to. Every top GND pad has its own via (rule 65), which is enough for a 23.6 x 16.2 mm, low-speed 5 V board.
- **Board grown, not exceptions:** with the 2.5 mm assembled-body rule (rule 26) C4 (2.10 mm from the top edge) and D1 (2.31 mm from the right edge) failed on 23.2 x 15.3 mm. Rejected: documenting both as deliberate edge parts (rule 13); C4 is not an edge part by function, and moving C4/D1 inward breaks the 0.5 mm courtyard gap (rule 37) or the hole free circles (rule 18). The outline became 23.6 x 16.2 mm (needs 16.11 mm because the parts are not centred vertically; keeping them on the 1.27 mm grid beat re-centring by half a step).
- **Hand routing of signals:** the autorouter (default vias 0.3/0.2 mm; 5-7.5 mm runs on the bottom layer for DISCH, THRES and OUT; vias 0.05-0.23 mm from pads) broke rules 61, 65/16 and 66, so all copper is explicit and the autorouter is off. Rejected: a 0 ohm jumper or a detour for the two crossings (rule 65 Don't, CIRCUIT_RULES G7 Don't).
- **Rule 62 at R1 and R3:** a V5 trace of 0.3 mm (rule 14) meets a 0.15 mm signal on the other pad, and tscircuit traces have one width, so the neck of rule 62 cannot be drawn. Rejected: widening T11/DISCH/T12/T13/LED_A/OUT to 0.3 mm (cascades through the whole timing network, leaves no "standard" signal width for rule 14, and the 0.67 mm gap between THRES and CTRL gets tight for OUT); starting V5 from a 0.15 mm stub (no place for it: a trace must start on a pad or via, and no vias on V5, rule 15). R1.pin1 also carries three V5 branches (T1, T6, V5_C4). Accepted as an exception for two 0603 joints on a board without a large copper area at the pad; check the solder preview of R1/R3 in the JLCPCB order review. C1 and C2 are balanced instead with 0.15 mm GND stubs.
- **Fabrication export:** `npm run check:full` is clean (no shorts) and `npm run export:gerbers` produces `dist/gerbers.zip` (Gerbers, drills, `bom.csv`, `pick_and_place.csv`).

## Finding JLCPCB parts

Query the [jlcsearch](https://jlcsearch.tscircuit.com/) JSON API. Prefer basic parts (`is_basic=true`) and pick the highest stock. Example for 22k 0603 resistors:

`https://jlcsearch.tscircuit.com/resistors/list.json?package=0603&is_basic=true&is_preferred=&resistance=22000`

Then open the part page (`https://jlcpcb.com/partdetail/C<number>`) and confirm it says `PCBA Type: Economic and Standard`; jlcsearch does not expose this flag. Record the chosen part as `supplierPartNumbers={{ jlcpcb: ["C..."] }}` in `index.circuit.tsx`. Only fall back to non-basic (extended) parts if no basic one fits.

Also browse [tscircuit datasheets](https://tscircuit.com/datasheets) to discover elements.

## Setup

Requires Node and [Bun](https://bun.sh) (`tsci` runs under Bun; make sure `~/.bun/bin` is on PATH).

```bash
npm install
npm start           # tsci dev: interactive preview
npx tsci build      # compile and validate, output in dist/
npx tsci snapshot -u   # regenerate the schematic SVG snapshot (__snapshots__/index.circuit-schematic.snap.svg, embedded at the top of this README)
npm run export:images    # rebuild and refresh docs/images/{pcb,3d}.png (embedded at the top of this README)
npm run update:skill   # re-install the latest tscircuit AI skill into .claude/skills/tscircuit/ (review with git diff, commit with skills-lock.json)
```

Before sharing or fabricating, work through the checks in order: `tsci check netlist`, `schematic-placement`, `placement`, `routing-difficulty`, then `tsci build`, then `npm run check:vias`, then `tsci check shorts` (`npm run check:full` runs the last three in this order). See `.claude/skills/tscircuit/CHECKLIST.md` for the pre-fab checklist.
