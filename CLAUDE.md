# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A tscircuit PCB project built from the `agentic-pcb/example-base` template: PCB designs are written as React/TSX and compiled by the `tsci` CLI (local binary in `node_modules/.bin/tsci`, from the `tscircuit` package). A board is a `*.circuit.tsx` file that default-exports a function returning a `<board>`; the main one is the `mainEntrypoint` in `tscircuit.config.ts` (`index.circuit.tsx` in the template; `tscircuit.config.json` is only a `$schema` stub). `*.circuit.tsx` files are built automatically, so reusable pieces (wrapper components, shared data) go in plain `.tsx`/`.ts` modules, e.g. under `lib/`. Outputs go to `dist/`. `.tscircuit/` is a cache/autorouter-artifacts dir (gitignored). There is no test suite. The `tsci` binary's shebang is `env bun`, so Bun must be on PATH. Bun is installed at `~/.bun/bin` and `~/.zshrc` adds it to PATH, but Claude's Bash tool doesn't load `~/.zshrc`, so run `export PATH="$HOME/.bun/bin:$PATH"` first there (otherwise `tsci` fails with "bun: No such file or directory"). Plain `node` can't run `tsci` (a dependency uses directory imports) and `tsx`, the CLI's non-Bun fallback, isn't installed. We chose to keep Bun rather than add `tsx`.

`@tsci/*` packages resolve from the tscircuit registry via `.npmrc`; add them with `tsci add <author/pkg>` (imports look like `@tsci/author.pkg`).

If the README Status still says "Template: placeholder", the board file holds only the template placeholder (one resistor, one LED, one trace) and no real design exists yet: it is replaced, together with the README and the images derived from it, by the workflow below.

## This file is the template, README.md is the project

This file is identical in every project built from the template and holds only what is true for all of them. Everything about this particular project is in `README.md`: what the board is, its requirements and status, its board files, script names, tooling, rule exceptions and audits, and its own helpers and gotchas.

- Read the README **Project map** section before any work, and the rest of the README before changing the design.
- Never edit this file in a project; edit it only in `agentic-pcb/example-base` (the repo whose `package.json` name is `example-base`). `npm run update:claude` overwrites it with the current copy from example-base `main`.
- When you learn something new: if it is about this board, write it into the README (Project map or Design notes); if it is true for any tscircuit board, it belongs in this file upstream, so tell the user instead of changing the local copy.

## Workflow: building a project from README.md

`README.md` is the brief. When asked to build or design the project:

1. Read the **Requirements** section. If any bullet is still `TODO` or ambiguous (power input, board size, connectors, key values), ask the user before designing. Don't invent power rails, board outline, connectors or mounting holes. The layer count is not open: every board is 2-layer (see "Conventions and rules"), unless the Requirements name another one.
2. Replace the placeholder in the board file. Choose parts (see "Choosing JLCPCB parts" below, and read `CIRCUIT_RULES.md` for part and value choice), compute values (write the calculation into README Design notes), and record each assembled part's `supplierPartNumbers` in the TSX (the TSX is the BOM; no separate BOM in the README).
3. Iterate with the tiered checks below; fix schematic layout per the schematic rules (LAYOUT_RULES.md 19-20, 29-36; PCB 37-43; part-specific 44-60; manufacturing 61-63; layers and vias 64-66).
4. Keep `README.md` current as you go: Status, Project map, Design notes (what and why), Decisions (including rejected alternatives), Open questions, and once the board exists the two rule audits (layout: one row per rule; circuit: one row per applicable rule). Regenerate the embedded images after schematic/layout changes.
5. Rename for the new project: the README `# title` and the `name` in `package.json`. In a project (any repo other than example-base) delete the local `LAYOUT_RULES.md` and `CIRCUIT_RULES.md`: they live in example-base and are read by URL, so never recreate them. Fill the README Project map.

Docs-only edits need no checks. Never run `tsci push` or place orders unless explicitly asked. Electrical safety and manufacturability remain the user's responsibility.

## README images

The images at the top of `README.md` are, for each board, the schematic SVG `__snapshots__/<board>.circuit-schematic.snap.svg` (regenerate with `npx tsci snapshot --schematic-only -u` after schematic changes) and the PNGs under `docs/images/` (`pcb.png` and `3d.png` for a single board; the README Project map lists the paths otherwise) (committed copies of `tsci build` output, since `dist/` is gitignored; regenerate with `npm run export:images` after layout changes). The PCB SVG snapshot is not embedded; it only serves as the baseline for `tsci snapshot --test`.

## Commands

- `npm start` — `tsci dev`, interactive preview server (interactive visual feedback only; prefer `tsci build` for iteration)
- Script names: a single-board project has the plain names used below. A project with several boards has one script per board with a `:<board>` suffix and no bare name (`check:wiring:controller`), and its scripts pass the board file to `tsci`. The README Project map lists the boards, their scripts and any project-specific script
- `npm run check:fast` — `tsc --noEmit`, plus `eslint .` and `prettier --check .` when the optional Prettier + ESLint setup below was added (see `package.json`; then also run `npm run format` after editing TSX); the only JS-level check (no tests), catches wrong prop names/types. `check:wiring` adds netlist + schematic-placement; `check:full` adds `tsci build` + `check:vias` + `tsci check shorts`
- `npm run check:vias` — `node scripts/check-vias.mjs dist/<board>/circuit.json`: reads the last `tsci build` output and fails when a via or plated hole is in a JLCPCB extra-charge tier (LAYOUT_RULES.md rule 66); run it after `tsci build`
- `npm run update:skill` — re-installs the vendored `.claude/skills/tscircuit/` from upstream (`tscircuit/skill`); never edit that folder by hand. `npm run update:llms` fetches the docs dump. `npm run update:claude` replaces this file with the copy from example-base `main`
- `npx tsci build [file]` — compile and validate; without a file it uses the `mainEntrypoint` of `tscircuit.config.ts` (or `index.circuit.tsx`), and in a repo with several boards it builds all of them, so pass the file there. Add `--pcb-png` or `--all-images` for renders
- `npx tsci snapshot [--pcb-only|--3d]` — regenerate visuals; `--test` fails on visual diffs without overwriting
- `npx tsci export <file> -f <format>` — `schematic-svg`, `pcb-svg`, `readable-netlist`, `specctra-dsn`, `gltf`/`glb`, `kicad-library`
- `npx tsci search [--jlcpcb|--digikey|--mouser|--kicad|--tscircuit] "<query>"` and `npx tsci import "<part>"` — find and import parts (DigiKey/Mouser are discovery only; import works for JLCPCB and the registry)
- Run `npx tsci <cmd> --help` rather than guessing flags.

Check order (each stage gates the next):
1. `tsci check netlist` -> 2. `tsci check schematic-placement` -> 3. `tsci snapshot` + `tsci check placement [file] [refdes]` -> 4. `tsci check routing-difficulty` -> 5. `tsci build` -> 6. `tsci check shorts` (after routing; any short exits 1 and writes `checks/check-shorts/`; fix, don't dismiss). Don't finalize until schematic-placement and placement are clean. DRC errors can be ignored early on. For routing problems, use `tsci build --autorouter-debug --autorouter-debug-dir dist/autorouter-debug`.

When to run checks (tiered, not everything every time):
- After every edit to a board file: `npm run check:wiring` (check:fast + netlist + schematic-placement; must stay clean).
- After layout/footprint/position changes: go through the PCB review list at the end of LAYOUT_RULES.md (`tsci check placement` also flags the courtyard overlaps of rule 37), and also `npm run export:images` (the README embeds the committed PNGs) and `npx tsci snapshot --pcb-only -u`; after `sch*` or schematic changes use `npx tsci snapshot --schematic-only -u` (the README embeds that SVG), `tsci check placement` and `tsci check routing-difficulty`.
- Before committing a design change and before fab: `npm run check:full` (check:wiring + `tsci build` + `check:vias` + `tsci check shorts`). Before ordering only: `npm run export:gerbers`.
- Schematic SVG export (`tsci export -f schematic-svg`) is for inspecting schematic changes, not a gate.

## Optional: Prettier + ESLint

The template ships without a formatter or linter; whether this project has them shows in `package.json` (`format`, `lint`) and in the README Project map. When the user wants one (ask first, don't add it unprompted), a light setup that worked in the `bedroom-clock` project:

- Dev deps: `prettier eslint @eslint/js typescript-eslint eslint-config-prettier eslint-plugin-simple-import-sort`. Skip `eslint-plugin-unicorn`: it flags the short geometry names and fights compact math code.
- `.prettierrc`: `singleQuote: true`, `trailingComma: "none"`, `endOfLine: "lf"`, **`printWidth: 300`** so each tscircuit element (`<chip ...>`, `<smtpad ...>`, `<trace pcbPath=...>`) stays on one line. Ask whether to keep semicolons (Prettier default; the user's other repos use them) or set `semi: false`.
- `.prettierignore`: `dist`, `.tscircuit`, `.claude`, `__snapshots__`, `docs`, `node_modules`, `package-lock.json`, `*.md`, `*.json` (never reformat the vendored skill, snapshots or the README tables).
- `eslint.config.mjs` (flat config, same ignores): `js.configs.recommended`, `tseslint.configs.recommended`, `eslint-config-prettier`, plus rules `curly: ['error', 'multi']`, `simple-import-sort/imports` and `/exports`, `@typescript-eslint/consistent-type-imports` (inline type imports).
- Scripts: `format` = `prettier --write .`, `lint` = `eslint .`, and `check:fast` = `tsc --noEmit && eslint . && prettier --check .` (so `check:wiring` and `check:full` inherit it). Run `eslint . --fix` and `npm run format` once as their own commit.
- Verify formatting changed no design: `npx tsci snapshot --pcb-only --test` and `--schematic-only --test` must show no diff. Then note the tooling in the README Project map.

## Conventions and rules

- Every board is a 2-layer board: top and bottom copper, `<board layers={2}>` written out (2 is also the tscircuit default). Never `layers={1}` (no plated holes at JLCPCB, so no vias) and never 4 or more (no inner layers, no blind or buried vias); when a design does not fit on two layers, stop and ask the user instead of adding a layer. Parts and traces go on the top, the bottom is the GND pour plus short crossing hops. Vias are what make this work and they cost nothing: use one to cross a trace (via, short bottom segment, via), beside every top-layer GND pad to reach the pour, and under hot pads; don't detour a trace or add a 0 ohm jumper to save a via. Only supply nets avoid them (rule 15), and none sits in or at an SMD pad (rule 61). The via is 0.6 mm pad / 0.3 mm hole, which JLCPCB makes at no extra charge, and every board sets it: `<board pcbStyle={{ viaPadDiameter: 0.6, viaHoleDiameter: 0.3 }}>`. Without that prop the installed core makes every via (autorouted, `<via>` without sizes, `pcbPath`, copper pour) with a 0.3 mm pad and a 0.2 mm hole, which JLCPCB charges for (`minViaPadDiameter`/`minViaHoleDiameter` on the board only reach the autorouted ones). Write explicit ones the same size (`<via fromLayer="top" toLayer="bottom" outerDiameter="0.6mm" holeDiameter="0.3mm" />`). `npm run check:vias` fails on any via or plated hole in a paid tier (hole under 0.3 mm, via pad under 0.45 mm). Rules: `LAYOUT_RULES.md` 64-66, `CIRCUIT_RULES.md` G9.
- Two shared rule files, split by one test: a rule that can be checked from the netlist and BOM alone (which part, which value, which pin connects to what) is in `CIRCUIT_RULES.md`; a rule that needs coordinates, copper, layers, silkscreen or the schematic drawing is in `LAYOUT_RULES.md`. They live in `agentic-pcb/example-base` and are not copied into projects: read the local file when it exists (example-base itself), otherwise fetch the raw URL verbatim with `curl -fsSL` (not WebFetch, which summarises). The README Project map says which boards they apply to. Precedence: datasheet of the actual part, then the part-specific layout rules (44-60), then the generic layout rules (1-43).
- PCB layout and schematic follow `LAYOUT_RULES.md`, the single source of truth at https://raw.githubusercontent.com/agentic-pcb/example-base/main/LAYOUT_RULES.md: alignment, routing, mounting, schematic and placement rules (1-43, incl. GND copper pour, rule 16, and no 90 degree trace corners, rule 17) and part-specific layout rules (44-60: regulators, crystal, USB, RF and antenna, isolation, relay) and manufacturing rules (61-63: no via in an SMD pad, equal copper on both pads against tombstoning, no silkscreen under small parts) and layer and via rules (64-66: two copper layers only, what vias are for, via size), 66 in all; decoupling caps within 3 mm of the IC power pin is a must (rule 24). A `Don't:` clause at the end of a rule, in either rule file, is a counter-example that names the mistake breaking the rule: check the design against it too. Read it before moving or adding parts, pads or labels; record exceptions in the README. The README holds the audit of each board against it (one row per rule): update it after layout changes, and when the rule numbers change upstream, renumber the table and the rule references in the README and in TSX comments. Designator size comes from `<board pcbStyle={{ silkscreenFontSize }}>`; a designator is moved with the `pcbSx={{ '& silkscreentext': { pcbX, pcbY } }}` prop of its part (offset from the part; `pcbStyle.silkscreenTextPosition` is typed but not implemented in the installed core). That `pcbSx` selector hits every silkscreen text of the part (pin labels, designator, group label), so a part with several texts hides its own and uses explicit `<silkscreentext>` elements. Check courtyard gaps (rule 37) from `pcb_courtyard_rect` in `dist/<board>/circuit.json` (`ccw_rotation` 90 swaps width and height).
- Part, value and wiring rules (which capacitor, resistor, transistor, regulator, fuse, relay, isolator, crystal or logic IC to use, and the wiring rules of ESP32, ATmega328P, STM32, RP2040) live in `CIRCUIT_RULES.md` at https://raw.githubusercontent.com/agentic-pcb/example-base/main/CIRCUIT_RULES.md. Read it before choosing or changing parts, values or wiring, go through its review list at the end, record exceptions in the README and keep the README circuit rules audit (one row per applicable rule) current. Each section ends with a "Layout:" line naming the `LAYOUT_RULES.md` rules of that part family; follow them at the layout step. Every rule there carries a source tag, and so do `LAYOUT_RULES.md` 44-63 and the sourced `Don't:` clauses (they cite the same Sources list); add a rule only with a source you read, and drop what you cannot source.
- Detailed guidance lives in the bundled skill: `.claude/skills/tscircuit/` (SKILL.md, CLI.md, SYNTAX.md, WORKFLOW.md, CHECKLIST.md, FOOTPRINTS.md, per-element docs in `elements/`, templates in `templates/`).
- Don't invent JSX props or CLI flags; confirm in `elements/*.md` or `--help`. Learn from https://docs.tscircuit.com/ before writing or changing circuit code, not only for what the skill doesn't cover. `https://docs.tscircuit.com/llms.txt` (same as `ai.txt`) is the whole docs set as one ~870 KB Repomix dump: run `npm run update:llms` to save it as `docs/llms.txt` (gitignored) and grep that file, never load it whole. The skill comes from https://github.com/tscircuit/skill (`npx skills add tscircuit/skill`).
- Define `pinLabels` and `pinAttributes` on chips before wiring traces. Reference pins by label (`U1.VCC`, `net.GND`).
- Prefer a footprinter string (`footprint="0603"`) over a custom `<footprint>`; read FOOTPRINTS.md before writing custom footprints. Exception: for a JLCPCB-specific part, `footprint="jlcpcb:..."` fetches from EasyEDA at build time and fails on HTTP 403 rate limits, so define a local `<footprint>` instead (pad geometry copied from the JLCPCB part). Custom footprints get no 3D body, so pass `cadModel={<cadmodel modelUrl={...} />}` with absolute URLs `https://modelcdn.tscircuit.com/jscad_models/<footprinter>.glb`. Don't import local `./models/*.glb`: `tsci build` resolves them but the `tsci dev` 3D viewer 404s on the relative path. Check both `3d.png` and the dev 3D tab after changing.
- The parts engine is disabled (`tscircuit.config.ts` `platformConfig.partsEngineDisabled`; `build`/`snapshot`/`export` also take `--disable-parts-engine`, `dev` and `check` don't). With it on, every part carrying `supplierPartNumbers` triggers an EasyEDA footprint cross-check that returns HTTP 403 `source_part_not_found_warning`s. A JLCPCB login does not help; tsci uses no JLC credentials. Pin parts via `supplierPartNumbers` yourself (the engine's auto-picking is off). The BOM export only lists parts that carry a supplier part number. A part without `supplierPartNumbers` (e.g. the template placeholder) gives a "missing a manufacturer part number" build warning; it goes away once the part has one.
- For USB-C use `<connector standard="usb_c" />`, not a JLCPCB import.
- Always keep a `<schematicsheet>`: without one `tsci build` warns "No <schematicsheet> was found" (the warning badge in `tsci dev`). Give it an explicit `sheetWidth`/`sheetHeight` sized to the circuit (one `schX`/`schY` unit is about 10 mm of sheet and symbols are only 1-2 units wide, so keep part coordinates within a few tens of units; the sheet is centred near (5, -5), and 260 x 180 mm holds about x -8..18, y -14..4), because the default A4 frame is huge and shrinks the circuit to a speck in the README image. Parts and labels must sit inside the frame with margin (the build warns "extends outside the drawing area" otherwise; two parts need about 70x50mm), then re-render to check. Every part needs `schSheetName="<sheet name>"`; wrapper components must forward it to the chip.
- Group schematics with `<schematicsheet>`/`<schematicsection>` once a design has 5+ components. Split the diagram into logical blocks (e.g. power input, core IC, timing network, outputs): give each block its own `schSectionName` and keep its parts clustered by `schX`/`schY`, with a clear gap between blocks (LAYOUT_RULES.md rule 19); draw inputs left, core middle, outputs right (rule 20).
- Keep schematic wires from overlapping (LAYOUT_RULES.md rules 19-20 and 29-36 cover block layout; the auto-layout can run wires of different nets along the same line, which looks like a false connection). Set `schX`/`schY`/`schRotation` on every part instead of trusting auto-placement, then render with `tsci export <board file> -f schematic-svg -o <scratchpad>/x.svg` and look at it (`rsvg-convert -w 4000` to PNG, crop), then go through the Schematic review list at the end of LAYOUT_RULES.md. Fix by: rotating parts so pin1/pin2 face their neighbours, reordering `schPinArrangement` so pins that share a net sit on the same side and in the order of the parts they connect to, spacing clusters apart, and checking `tsci check schematic-placement` hints. A hop mark where wires cross is fine; a dot or shared segment between different nets is not. Swapping two pins in `schPinArrangement` only redraws the symbol (netlist and PCB unchanged).
- Same-net pins closer than `schMaxTraceDistance` (5 schematic units when set on the board) get an auto-drawn wire between them, even across blocks. To keep a separate block (e.g. a power input) connected by net labels only, place it more than ~5 units from every pin of those nets in the main block, directly below/beside it without widening the picture needlessly.
- `tsci check schematic-placement` hints like `TwoPinComponentCouldBeFlipped` count wire turns only and can make the drawing worse. Render before applying a hint; an unapplied hint is informational (the check still exits 0).
- `tsci snapshot --schematic-only` does not overwrite a changed snapshot ("Run with --update to fix"): pass `-u`. `tsci build` also warns on unnamed `<trace>`s and prints "Could not save autorouting paths…" on every run; neither blocks the build.
- Schematic wire vs label: a `net.X` trace always draws as a label stub, and a named direct trace (`name="..."`) draws a flag. To show a real wire, connect the pins directly (pin to pin). Board `schTraceAutoLabelEnabled` + `schMaxTraceDistance` (e.g. 5) turns long runs into labels; a large distance (20) draws every power net as one long tangle. Only change `sch*` props for layout work, so the netlist and PCB snapshot stay unchanged (verify with `tsci snapshot --pcb-only --test`).
- Choosing JLCPCB parts: query `https://jlcsearch.tscircuit.com/<category>/list.json` (e.g. `resistors/list.json?package=0603&is_basic=true&is_preferred=&resistance=22000`), prefer basic parts, pick the highest stock, and record the choice as `supplierPartNumbers={{ jlcpcb: ["C..."] }}` on the part in the TSX. Only the `resistors` endpoint has been confirmed; check other categories before relying on them. Also use https://tscircuit.com/datasheets to discover elements/parts (not yet explored; check what it offers first). Not needed until a design actually needs parts.
- Assembly is ordered as JLCPCB **Economic** (unless the README Requirements say otherwise): only use parts whose jlcpcb.com part page (`https://jlcpcb.com/partdetail/C<number>`, text "PCBA Type") says "Economic and Standard", never "Standard Only". jlcsearch does not expose this flag, so check the page (e.g. with the browser tool) before choosing or swapping a part.
- Through-hole parts that are hand-soldered (e.g. headers) get `doNotPlace` so they stay out of the JLCPCB BOM/CPL. Use `<connector>`, not `<chip>`, for J-prefixed parts.
- A `<group>` re-lays out its children on the schematic; without groups, parts carry absolute board and schematic coordinates.
- Hand-routed copper (`<trace pcbPath>`, e.g. for LAYOUT_RULES.md rule 17): `pcbPath` points are in the frame of the component that owns the trace's `from` port (its position and rotation), relative to the *centre* of that part, not the pad, and tscircuit adds the pad ends itself. So either start the trace at a 0° part and offset the points by its `pcbX`/`pcbY` (run it from the other end when the part is rotated), or convert the points into the part's frame. A via inside a path needs a wire point at the same spot on both sides; the crossing hop of rule 65 is such a path: top, via, a short bottom segment, via, top. The explicit trace of a through-hole pin always starts on the top layer, so a bottom-layer branch from such a pin needs a via. A capacitor between a power and a ground net gets a 1 mm straight-line limit on traces from its pins (`maxDecouplingTraceLength`) and tscircuit then skips autorouting: raise the prop and start no long trace at that capacitor. Hand-route a whole net at once: fixing only a few legs makes the autorouter produce hairpins on the rest. `<board routeRemaining={false}>` turns the autorouter off for a fully explicit board. A pin-to-pin trace draws a schematic wire; add `schDisplayLabel` to keep the label look (verify with `tsci snapshot --schematic-only --test`). Keep the path helpers (corner cutting, frame conversion) in the board file and name them in the README Project map.
- Fabrication outputs (Gerbers/BOM/PnP): `npm run export:gerbers` writes `dist/gerbers.zip` (it wraps `tsci export -f gerbers`; the zip holds Gerbers, drills, `bom.csv` and `pick_and_place.csv`). The `tsci dev` export UI also works. `tsci export` warns "cannot verify jlcpcb pick-and-place rotation" for SMD parts, so rotations in `pick_and_place.csv` need a human check in JLCPCB's assembly preview before ordering.
